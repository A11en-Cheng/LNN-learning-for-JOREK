# 工程踩坑清单（2026-09-30 整理）

按“数据 → 环境 → 训练 → 物理”分类。每条都写出**现象 → 真因 → 规避方式**，
避免以后重复排查。新坑继续往这里追加（append-only）。

## 数据契约

1. **`psi`/`Z_j` 通道对调**（已修）
   - 现象：所有 psi 诊断离谱（ψ_n、椭圆关系、非局域表都对不上）。
   - 真因：`H5_VALUES_INDICES=(2,1,0,...)`；而 `mod_export_restart.f90` 是直接拷贝
     `node%values`，H5 顺序就是模型顺序（psi,u,zj,w,rho,Ti,Vpar,rhon,Te）。
   - 规避：identity 映射 + 回归测试；用数据自证（轴心值 ≈ `psi_axis_t`）。
2. **`contain_node` 全为 0**
   - 现象：体积/质量加权全零、表面平均全 NaN。
   - 真因：这些 H5 里连通性在 `vertex`，`contain_node` 是空壳。
   - 规避：一律读 `vertex`（4×n_elem，1-based）。
3. **H5 `x` 的轴序是 `[dim, dof, tor, node]`**
   - 现象：单元几何重建只在一个角点正确、质量矩阵整体错位数量级。
   - 真因：把 `[dof, vertex]` 当成了 `[vertex, dof]`（局部单元需转置）。
   - 规避：进入单元计算前显式 `[vertex, dof, dim]`，并做“角点重建 == 节点坐标”自检。
4. **`frame_indices` 是帧缓存位置，不是 JOREK 步号**
   - 现象：`jorek000062.h5` 找不到文件。
   - 真因：manifest 存的是 aligned frame 列表下标。
   - 规避：取文件一律走 `store.frames[position].state_path`。
5. **run 目录里混有跨 run 杂帧/重复 run**
   - 现象：`scan_1d21_ang12_massloss_neon/jorek008700.h5` 的 `t_now=19710`（邻帧 ~10600）；
     `scan_1d22_ang12..._v200` 与 `_v300` 字节级相同。
   - 规避：按 `index_now` 取帧；语料去重（v200 已删，8 run）。
6. **诊断文件是“上一次调用的快照”，不是逐帧数据**
   - 现象：`nonlocal_array.dat` 用到别的帧上高估 60–150 倍；run 目录的 `abl_history.dat`
     只有一行非零。
   - 真因：`int3d_new` 每步覆盖该文件；`abl_history.dat` 是坏诊断产物。
   - 规避：非局域表**逐帧重建**（`src/data/nonlocal_table.py`）；
     `abl_history.dat` 用 `jorek2_diagno_spi` 重新生成并核对 H5 的 `xtime_spi_ablation*`。

## 环境与执行

7. **`ulimit -s unlimited` 必须与命令同一个 shell**
   - 现象：JOREK 二进制刚启动就 `SIGSEGV`（`si_addr` 在栈上）。
   - 真因：写成 `(ulimit -s unlimited) && cmd` 时限制只在子 shell 生效。
   - 规避：`ulimit -s unlimited && export OMP_NUM_THREADS=1 && mpirun -np 1 ./binary < namelist`。
8. **沙箱内 CUDA 不可见**
   - 现象：`torch.cuda.is_available()=False`、`Can't initialize NVML`。
   - 真因：沙箱禁止 NVML/设备访问（与 MPI socket 被拒同源）。
   - 规避：训练在沙箱外跑（GPU 实测 RTX 5070 Ti 16 GB）。
9. **诊断程序通过软链写回数据目录**
   - 现象：`Ne_charge_distribution.dat` 被改写（内容恰好与未动过的 run 一致，MD5 相同）。
   - 真因：隔离目录用“全量软链”，输出文件名不在删除清单里。
   - 规避：所有**输出文件名**必须在运行前 `rm` 掉软链（见 `.scratch/regen_diagno.sh` 的
     `OUTPUTS`/`REWRITE` 清单），并优先 `tmp + mv` 写文件。
10. **`timeout ENV=... cmd` 不工作**
    - 现象：`timeout: failed to run command ‘PYTORCH_CUDA_ALLOC_CONF=…’`。
    - 规避：`export VAR=…` 后再 `timeout …`，或用 `env VAR=… timeout …`。
11. **`pkill -f "pattern"` 会杀掉自己的 shell**
    - 现象：命令莫名以 143 退出、后续输出丢失。
    - 真因：bash 的命令行里含同 pattern。
    - 规避：采样进程用 `timeout N nvidia-smi …` 自行结束，不用 `pkill`。

## 训练与网架

12. **burn-in 留在 autograd 图里 → 45 GiB OOM**
    - 真因：30 步 cell 调用全保留在图中做 BPTT，而 loss 只从监督区间开始。
    - 规避：burn-in 用 `torch.no_grad()`（hidden 只当数值初值）。
13. **批量化时 edge_index 没有按窗口偏移**
    - 现象：`compute_gradient` 报 `size of tensor a (4125) must match b (132000)`；
      以及 `too many values to unpack`（把 offset 当成第三行 `cat` 了）。
    - 规避：`edges = edges_single.repeat(1, b) + offsets`（offset 是 `[1, b*E]`，
      广播到两行），不是 `cat`。
14. **torch FEM 梯度传了全零 counts**
    - 现象：torch 版与 numpy 参考最大偏差 7e2（参考 rms 5.8），像“精度问题”其实是权重错。
    - 真因：节点被 1–4 个单元共享，必须累计 `count` 再平均；传零 → 除以 1。
    - 规避：让 `nodal_gradient_torch` 自己累计 counts（默认 `counts=None`）。
15. **DataLoader 多 worker 反而更慢**
    - 实测：`num_workers=4, prefetch=4` → wall time 2m58 → 4m04，利用率中位 50% → 34%。
    - 真因：worker 间搬运窗口张量的 IPC 开销 > 省下的窗口拼装时间（瓶颈是内核启动开销）。
    - 规避：Phase-3/4 用 in-process（`--num-workers 0`）；要压尾部再考虑预拼装缓存。
16. **逐点 MSE 掩盖拓扑错误**
    - 现象：`psi` R² 0.984，但磁轴偏 7 cm、H1 误差 0.69，`omega` 总量误差 −206%。
    - 规避：结构指标进 Gate（H1、磁轴中位/p90/max、积分预算），并加 `λ_H1`、`λ_axis`。
17. **纯 H1 推不动 argmax 型拓扑量**
    - 现象：λ_H1 从 0 加到 0.1，H1 单调改善但磁轴中位几乎不动；λ=0.3 时 p90 反而变差。
    - 规避：加显式 soft-argmax 轴损失（λ_axis=0.3 时中位 3.6 cm / p90 5.4 cm / max 5.8 cm）。

## 物理与残差

18. **把 gather 归一化多除了一次**
    - 现象：组装的 RHS 比记录解大 ~1e6。
    - 真因：密度通道里 `Z_imp=w⟨Z⟩·timesteps` 与 `1/(n_steps·timesteps)` 相消，
      RHS 不需要再除 `gather_time`。
    - 校验：logfile 的 `Total generated electrons` == `Σ w⟨Z⟩`（差 0.07%）。
19. **`_relative_norm = |Σterms| / Σ|term|` 会被单个刚性项支配**
    - 现象：接入真实 κ∥（`ZK_i_par=1.67e5`、`ZK_e_par=4.1e6`）后两条能量方程残差
      饱和到 ~1.0。
    - 真因：`κ∥·div_par(T)` 量级压倒其它项，节点配点算子的离散误差同时进入分子分母。
    - 处置：能量通道暂不进入物理损失；先做 κ∥ 的物理一致离散（通量坐标/FEM 一致），
      或把 κ∥ 项从相对范数里剥离单独约束。
20. **定义类残差是最有效的物理信号**
    - 实测（真实系数）：`current_definition` 0.077→0.946、`induction` 0.134→0.981、
      `vorticity_definition` 0.231→4.637（本底→模型），而能量通道本底 1.0。
    - 用法：第一轮 λ_phys 只启用这三条；λ_phys=0.05 已把 `vorticity_definition` 2.57→1.45。
    - **本底分布重做（2026-09-30，dense 口径）**：旧的"0.134/0.077/0.231"只是**一个窗口、
      一个区间**的读数，而且用的是旧 30+1 监督密度，不足以标定 λ_phys。
      新工具 `tests/check_residual_floor_stats.py` 在**全部 8 个 run 的 196 个 val 窗口 /
      588 个监督区间**上，逐区间用**该区间起始帧自己的系数**（`--phys` 用同一约定）+ 记录
      投影做教师源，给出分布（中位/p10/p90，见 `.scratch/n/residual_floor_stats.json`）：

      | 通道 | 中位 | p10 | p90 | 逐 run 中位范围 |

      | `induction` | 0.422 | 0.119 | 0.677 | 0.17–0.53 |
      | `current_definition` | 0.085 | 0.074 | 0.152 | 0.07–0.15 |
      | `vorticity_definition` | 0.048 | 0.027 | 0.159 | 0.016–0.44 |
      | `vorticity`（eq2 全式） | 0.946 | 0.790 | 0.991 | ≈0.82–1.0 |

      分布证实；② `induction` 本底大且**逐 run 分散**（0.17–0.53）；

      不是压到 0；④ `charge_state` 在我们的公式里恒为 0，**永远不要**放进损失（它检验的是

    - **更正（2026-09-30，同日）**：当时把 `induction` 本底归因于"JOREK 的 50 步
      Crank–Nicolson vs 我们的一阶后向差分"，**实测被否**：
      `tests/check_residual_time_scheme.py` 用同一套空间算子、只换时间差分
      （后向 `(u_{k+1}−u_k)/Δt` vs 中心 `(u_{k+1}−u_{k−1})/(t_{k+1}−t_{k−1})`），
      v400 的 45 个区间上 `induction` 中位 0.177 → 0.164（**只降 7%**），

      时间差分无关，只反映状态本身）。⇒ 本底**由空间算子离散误差支配**，不是时间格式；

      vorticity_def），即插值轨迹违反离散方程的程度是数据本身的 ~8–11 倍。
25. **残差里的投影源用了 z-score 单位（已修）**
    - 现象：`density/impurity/induction/current_definition/vorticity_definition` 对本底无影响，
      但 `vorticity`（压力项要 `Z_imp` → `n_e`）与 `electron_energy`（辐射/电离源）在
      "源被 z-score"与"源是物理单位"两种输入下差百分之几到几倍：
      `vorticity` 本底 0.909 → **0.946**，`parallel_momentum` 0.997→0.9996，
      `electron_energy` 0.9997→**1.0000**。
    - 真因：数据集把 `source` 做了 z-score（`(s−mean)/std`），而 `_source_controls` 只有在
      显式传入 `source_stats` 时才反归一化；训练器与旧的 check 脚本都没传（`source` 被当成
      物理量代进 `Z_imp`、`rad_sink`、`d_ion`）。
    - 规避：`_physics_term` / `check_residual_floor_stats.py` / `eval_phase4_physics.py`
      统一传 `source_stats=(source_mean, source_std)`。当前三条 λ_phys 通道不含源项，
      所以修它对既有工作点**无影响**，但接入第二批（能量/压力相关）通道前必须修好。
26. **训练循环里 `source` 变量被物理项覆盖 → λ_phys>0 必崩（已修）**
    - 现象：dense 口径（10+3，每窗口 3 个监督步）一开 `--lambda-phys` 就
      `IndexError: index 12 is out of bounds for dimension 1 with size 5`
      （`_batch_loss` 的 `source[:, k + 1]`）；λ_phys=0 完全正常。
    - 真因：物理项循环里写了 `source = items[row]["source"][k + 1]`，把**批量张量**
      `source [B, T, nodes, 5]` 覆盖成**单个窗口的切片** `[nodes, 5]`；下一个 `k`
      迭代再对错误的张量索引就越界。只有"窗口内有 ≥2 个监督步 + λ_phys>0"才触发：
      旧的 30+1 基线每个窗口只有 1 个监督步（`k=30` 恰好是最后一次循环），
      所以历史那次 λ_phys=0.05 实验**掩盖了这个 bug**。
    - 规避：改名 `phys_source`；教训——训练循环里不要用与批量张量同名的局部变量，
      监督步数只有 1 时"能跑通"不代表接线正确。
    - 附带整理：旧的 `output/cfc_interp/phase4_phys_0.05`（30+1 基线产物）改名
      `phase4_phys_0.05_old30_1`，dense 工作点的三个 λ_phys 结果写在新目录，避免混用。
27. **三条残差的梯度尺度差 ~65×，等权平均让 `induction` 形同虚设**
    - 现象：dense 工作点上 λ_phys 从 0.02 扫到 0.1（5×），`vorticity_definition`
      的模型/本底比 8.7→4.3、`current_definition` 11.3→9.6，而 `induction` **恒定 7.39**
      （三个 λ 精确同值），完全没有响应。
    - 实测（对解码场求导，同一区间）：
      `|∂r/∂u_mid|, |∂r/∂u_end|` = induction `2.0e-2, 1.3e-3`；
      current_definition `2.2e-1, 1.1`；vorticity_definition `1.3, 6.1` → 差 **65×**。
    - 真因：`induction` 是 `ψ̇` 与 `{u,ψ}` 的**近抵消平衡**，残差是两个大项的小差，
      而 `_relative_norm` 又把两者都除进分母 → 对状态扰动极不敏感；
      三条通道数值同量级（0.99 / 0.82 / 1.18）但梯度差两个数量级，等权平均后 induction
      的权重 ~1%，等于没开。
    - 规避：**逐通道按本底归一化**（`r_c/floor_c`），必要时再按梯度尺度配 `w_c`；
      单纯调 λ_phys 对弱梯度通道无效（这条也解释了为什么"λ 越大越好"的扫法会误导）。
    - 附带结论：`train_phys` 随训练**上升**（0.61→0.95）不是 bug——模型拟合得越锐利，
      子区间残差越大；归一化之后要重新登记这条曲线作为收敛判据。
28. **`|Σterm| / Σ|term|` 相对残差在平台期梯度为零（已修，最重要的物理损失坑）**
    - 现象：`induction` 的模型/本底比在 **8 次独立训练**（原始口径 λ=0.02/0.05/0.1、本底
      归一化口径 λ=0.005/0.01/0.02/0.05）里恒为 **7.38–7.41**，模型侧残差恒为 0.995–0.999
      ——**恰好贴着 1.0**。λ 加大到让 data loss 直接崩掉（平均 R² 0.935→0.779）它也不动。
    - 真因：`_relative_norm = |Σterm| / Σ|term|` 的**值域就是 [0,1]**，1.0 是"各项完全不
      抵消"的顶点；在顶点附近的邻域里分子分母同步变化，函数**平坦（零梯度）**。
      JOREK 记录数据本底 0.13（两项近乎抵消），而学习出来的模型落在"不抵消"那一侧，
      于是这条通道既不能给梯度、也无法被优化——不是权重问题，是**损失函数形状**问题。
    - 规避：**冻结分母**（`detach_scale` / `--phys-keep-denominator` 的反面，默认已开）：
      数值完全不变（本底表照常用），但梯度变成 `sign(Σterm)/scale` 的**加权 L1**，平台期
      不再平坦。实测（同一区间、同一 checkpoint）：

      | 通道 | `|∂r/∂u_mid|` 冻结前 → 后 | `|∂r/∂u_end|` 冻结前 → 后 |
      |---|---|---|
      | `induction` | 3.8e-2 → **1.0e-1**（×2.7） | 2.2e-3 → **9.7e-2**（×44） |
      | `current_definition` | 2.2e-1 → 7.5e-1（×3.4） | 1.15 → 3.95（×3.4） |
      | `vorticity_definition` | 不变（分母是常数 `OMEGA_REFERENCE`） | 不变 |

    - 一般教训：**相对/归一化残差拿来做损失时，分母要不要 detach 是一个必须显式决策的
      设计点**；不 detach 就等于把损失变成"比例"而不是"不平衡量"，在饱和区失去梯度。
      新的相对残差都要问一句"它的值域有上界吗？上界处梯度是多少？"
    - 残留问题：即使 detach，`induction` 的有效梯度仍只有 `vorticity_definition` 的
      1/300（含本底归一化后 0.24 : 76），需要 `--phys-weights` 显式配平（见 #27）。
29. **场级 R² 掩盖了"增量根本没学会"——Phase 3 的 Gate 判据一直是错的**
    - 起因：`induction` 通道无论如何都饱和在 1.0，于是直接去看模型的**帧间增量**。
    - 现象（`tests/eval_phase3_structure.py` 新增 `dR2` 与 `|d|/|u|` 两列，
      `h1sweep_0.7` checkpoint、held-out v400、15 窗口、α=0.5）：

      | 场 | 场级 R² | relL2 | **增量 R²(dR2)** | 帧间增量/场量级 `|d|/|u|` |
      |---|---:|---:|---:|---:|
      | psi | 0.971 | 0.169 | **−155.2** | 1.4% |
      | Phi | 0.852 | 0.385 | **−3.58** | 18.0% |
      | Z_j | 0.976 | 0.155 | **−2.66** | 8.1% |
      | omega | 0.905 | 0.308 | **−1.22** | 20.7% |
      | rho / T_i / v_par | 0.968 / 0.987 / 0.937 | 0.18 / 0.12 / 0.25 | −2.10 / −2.26 / −6.64 | 10.1 / 6.4 / 9.1% |
      | rho_imp / T_e | 0.968 / 0.972 | 0.18 / 0.17 | −1.97 / −1.38 | 10.4 / 10.9% |

    - 读法：**所有 9 个场的 dR2 都是负的**，即模型对"这一步到底变了多少"的预测比
      "什么都不变"（persistence）还差。场级 R² 之所以好看（0.85–0.99），是因为
      **场本身的帧间变化极小**（psi 仅 1.4%），R² 被"复现输入场的空间结构"这一项支配。
      我们此前所有 Gate（R² ≥ 0.85、H1、磁轴）都是在测"像不像上一帧"，不是在测"动力学"。
    - 后果：物理损失看到的是**增量级的量**（ψ̇、Δ*ψ），而网络在增量上完全没有信号
      ⇒ 残差必然停在"不抵消"那一侧（#28），λ_phys 怎么调都只是把场抹平。
    - 规避：**验收指标改成增量口径**（dR2 > 0 是最低要求，目标 ≥ 0.8；再配 H1 与物理
      残差比）。`dR2` 已加进 `eval_phase3_structure.py`，以后所有 Phase-3/4 Gate 都用它。
    - 追查一（**训练远未收敛**）：100 epoch 的 data-only 训练

      **二阶信息也可以作为特征喂给网络**（用图 LSQ 版本，不用 FEM dof 版本）。
    - **封存决定 + 判定标准（2026-09-30，用户要求"不要延迟"）**：FEM(dof) 二阶路径
      确认**不可用**，已加 `RuntimeWarning` 并在 `laplacian_features` docstring 标注；
      关键诊断是**几何自检不充分**——它只检验一阶项（线性场二阶导为 0），所以
      `lap(R)=0` 通过的同时 `lap(R*Z)` 却是 1.9e4、`lap(R²)` 是 8.5e4（应 0 和 4）。
      真正的判定标准已写进 `tests/check_fem_second_order.py` 的"1b. analytic-field
      operator test"：**`lap(R)=lap(Z)=lap(RZ)=0`、`lap(R²)=lap(R²+Z²)=4`（~1e-8）**。
      根因定位到 dof↔基的尺度约定：`basis_2d_cubic_derivatives` 返回的是**带缩放的**
      Hermite 基（用"朴素基"重建 `s²` 得 1.25 而非 0.25），因此 `size` 数组与 dof 顺序
      必须精确配对，当前配对不正确（把 `size.transpose` 换成另一顺序能把误差从 8.5e4
      降到 2.1，说明方向对了但还不完整）。**不在关键路径上**：物理模块与
      `laplacian_features` 都使用已验证的图 LSQ 算子。
    - **二阶身份的严格验证（`Δ*ψ` vs `Z_j`、`Δ+Φ` vs `ω`）**：逐帧（4 帧）测
      **斜率 0.928–0.938 / 0.928–0.965、corr 0.9865–0.9867 / 0.9902–0.9951**，
      且残差与半径的相关只有 0.003–0.064 ⇒ 一个**近常数 5–7% 的幅度因子 + ~1% 散布**，
      **没有系统性空间偏差**。可以认为 `Z_j ≈ 0.93·Δ*ψ`、`ω ≈ 0.94·Δ+Φ`。
    - **口径更正（2026-09-30，用户质疑后复核）**：由上面这条**不能**推出"`Z_j`/`ω` 冗余、
      可降为辅助头"。补测偏差项本身：

      | 关系 | 斜率 | 偏差 rms | 偏差粗糙度 vs 场粗糙度 |
      |---|---:|---:|---|
      | `Z_j` vs `Δ*ψ` | 0.938 | 16.6% of `Z_j` | 0.359 vs 0.041（**粗 8.8×**） |
      | `ω` vs `Δ+Φ` | 0.957 | 12.4% of `ω` | 0.451 vs 0.031（**粗 14×**） |

      （粗糙度 = `rms(x − 邻域均值)/rms(x)`。）⇒ 偏差**比场本身还粗糙一个数量级**，
      说明那 12–17% 主要是**我们图 LSQ 算子的节点级离散噪声**，不是平滑物理剖面。
      结论修正为：① 二者的**光滑部分**高度相关，但**偏差正是 JOREK 里驱动 ψ 演化的
      电阻/惯性松弛项 `η(Z_j − Δ*ψ)`**，删掉等于删掉驱动；② 我们的算子精度不足以分辨
      该物理偏差，因此**没有依据**做降维；③ **保留 `Z_j`/`ω` 为完整状态量**，
      身份只用于一致性约束（已有定义类残差）、回归护栏与"便宜派生特征"。
      只有为了闭环推理压成本时才考虑 7 场 + 算子派生，且必须把偏差显式保留。
22. **导数特征没归一化 → A/B 消融里"加特征反而更差"**

23. **稀疏梯度算子的两个排序坑（已修）**
    - 背景：把图 LSQ 梯度预计算成稀疏矩阵（`build_gradient_operator`）：行索引按
      "分量优先"（`stack([2*row, 2*row+1]).reshape(-1)`），而值若按"边优先"
      （`(c*delta_pos).reshape(-1)`）拼就会**行值错配** → 与 `compute_gradient` 差 32 倍。
      修法：值也用 `stack([c*dR, c*dZ]).reshape(-1)` 对齐。
    - 另一个：输出轴序。`compute_gradient` 返回 `[nodes, features, 2]`，稀疏版最初返回
      `[nodes, 2, features]` → 广播比较时报"9 vs 2"，看起来像维度错误其实是转置。
      修法：`einsum` 后 `.permute(0, 2, 1)`。
    - 验证：修好后与 `compute_gradient` 相对误差 **7.9e-6**（float32 噪声）；
      **9 个场一次调用 1.56 ms**（对比逐场 2×2 求解 ≈25 ms）。
24. **反馈版导数特征自激发散（未解决，需要稳定化）**

      ① burn-in 与第一个子步用的是**记录帧**的导数特征，第二个子步突然换成**模型自己**

      a. 对导数特征做**硬 clamp**（按训练集分位数，如 1%/99%）；

      d. 训练前先统计"模型解码场的导数分布 vs 记录帧的导数分布"，确认是否越界。
    - 状态：反馈版**暂不进入主路径**；前馈版（B2）与 A 同级，保留。
    - **后续量化诊断（已做）**：同一时刻比较"记录帧导数特征 vs 模型自解码帧导数特征"
      （都在标准化空间）——**整体 rms 比 350×**，`rho[dZ]` 158×、`rho_imp[dZ]` **1242×**，

      机制确认无误：不是切片数据问题，而是模型自产特征严重越界。
    - **稳定化尝试（clamp ±5σ + 教师→反馈线性退火 + stop-gradient）**：比未稳定化版本
      好很多但仍远差于基线——psi R² 0.44→**0.78**（A/B2 是 0.97）、磁轴 23→**17 cm**
      （A/B2 是 3.3–3.6 cm）。**结论：反馈版不采纳**；导数特征这条线（前馈/反馈）都停放，
      除非有更强的稳定化（更长退火 + 特征一致性损失 + 对解码场先做物理裁切再求导）。
35. **symlog 改造引入的 autograd in-place bug（已修，只在与物理损失同开时暴露）**
    - 现象：`--input-deriv2 --lambda-phys 0.003` 训练在 `loss.backward()` 报
      `one of the variables needed for gradient computation has been modified by an
      inplace operation: [torch.DoubleTensor [4125]] ... version 4 vs 3`；
      同样的配置把 `--lambda-phys` 去掉就正常。
    - 真因：symlog 的反变换写成了 `restored[:, index] = sign(channel)*expm1(|channel|)`，
      其中 `channel = restored[:, index]` 是**视图**，随后对 `restored` 的原地写入让
      autograd 保存的视图失效（`AsStridedBackward` 版本号不匹配）。旧的
      `restored[:, index] = expm1(restored[:, index])` 恰好没暴露，因为 `expm1` 的反向
      只需要它的**输出**、不需要那个视图。
    - 规避：`transform_state` / `inverse_transform_state` 全部改为**非原地**
      （`torch.where(mask, replaced.unsqueeze(1), state)`）。
    - 教训：**"只有物理损失打开才崩"这类现象，先怀疑损失路径上的原地操作**；
      任何对 `requires_grad` 张量的 `[:, i] = f(x[:, i])` 都是隐患。
36. **物理损失的权重必须按当前 data loss 的尺度标定（否则会压垮动力学）**
    - 现象：在 gate6（导数+残差+动力学配平）基线上开 `--phys-floor auto --lambda-phys

    - 真因（尺度）：动力学配平把 data loss 压到 ~6.5e-4，而本底归一化的物理项在起点是

      用 `δ=(1−α)dt`（`--rho` 仍可覆盖）。
    - 教训：**任何 loss 项的权重都必须以"该项数值 × λ vs 数据项数值"来标定**，

37. **配平的判据是"梯度"，不是"数值"——而且先要分清"量级错"与"方向冲突"**
    - 工具：`tests/probe_grad_scales.py`（每个 loss 项单独反传一次，报
      `‖∂L/∂θ‖`、两两 cos、以及 encoder/cell/decoder 分组范数）。在 gate6 工作点实测：

      | term | loss | ‖grad‖ | enc / cell / dec |
      |---|---:|---:|---|
      | data | 1.04e-3 | **8.7e-4** | 1.3e-4 / 4.3e-4 / 7.4e-4 |
      | phys | 7.14 | **79.4** | 26 / 61 / 44 |
      | h1 | 3.65e-1 | 2.0e-2 | 9.0e-3 / 1.6e-2 / 8.7e-3 |
      | axis | 1.9e-3 | 8.1e-3 | 5.4e-3 / 5.2e-3 / 2.9e-3 |

    - 关键读数：**cos(g_data, g_phys) = 0.022**（几乎正交 ⇒ **不是方向冲突**）、
      **‖g_phys‖/‖g_data‖ = 1.4e5**（≈ `1/h²`，h~1cm 单元 ⇒ 二阶算子的固有放大）。
      按数值标定 λ=1.46e-5，按梯度标定 λ=**1.09e-6**，**差 13×** —— 这正是 gate8
      "数值只占 5% 却崩掉"的原因。
    - 结论（决策树）：**先测 cos 再选策略**——cos>0 且量级差 ⇒ 梯度归一化权重；
      cos<0 ⇒ 缩放无用，必须重表述（弱形式/限制通道/PCGrad 正交化）。
      本案走第一条。
    - 实现：`--grad-balance <target> --grad-balance-every K`（每 K 步两次额外反传测
      `g_data`/`g_phys`，令 `λ = target·‖g_data‖/‖g_phys‖`，EMA + 上限，逐 epoch 记录
      `lambda_phys_effective` 与 `grad_ratio_phys_data`）。自动免疫 loss 尺度变化。
    - **同一标准暴露的既有问题**：`λ_H1`（38×0.01 ≈ 0.38× 数据梯度）合理；
      **`λ_axis`（14×0.3 ≈ 4.2× 数据梯度）明显偏重**，应同法重标定。
    - **结构性修复（下一步）**：`1/h²` 放大是"逐点二阶导作用在节点解码场上"的固有性质。
      **弱形式（刚度矩阵）**算子的梯度尺度是 O(1)、且天然抑制节点噪声（同时能治
      "偏差比场粗 8.8×"那个问题），并且可以用**已验证可用的一阶基**组装，
      绕开 #21 那条坏掉的手工二阶链式法则。计划：自适应 λ 先解锁物理损失（本轮），
      随后做弱形式原型并把两者对比。
    - **自适应 λ 实测（gate9，2026-09-30）**：`--grad-balance 0.1 --grad-balance-every 10`
      让 λ 从 1e-5 自动收敛到 **1.7e-5 → 3.1e-6 → 3.3e-6**，与探针预测的 1.1e-6 同量级
      ⇒ **配平机制本身工作正常**。但结果仍是负面：

      | 配置 | 平均 dR2 | psi H1_rel | 轴中位 | 物理比 ind/cur/vort |
      |---|---:|---:|---:|---|
      | gate6（无物理损失） | **+0.194** | **0.046** | 0.38 cm | 5.96/8.51/3.53 |
      | gate8（静态 λ=1e-5） | −0.120 | 0.314 | 3.03 cm | 5.33/12.56/15.52 |
      | **gate9（梯度配平）** | **−0.167** | **0.313** | 2.69 cm | 5.33/12.56/**17.39** |

      训练侧 `train_phys` 从 6.6 顺利降到 3.8（确实在最小化残差），但**留出集三个通道全部变差**、
      动力学被摧毁。gate8（λ 大 3 倍）与 gate9 结果几乎相同 ⇒ **问题不在量级，在方向**：
      cos(g_data,g_phys)=0.02 意味着物理梯度几乎正交于数据梯度，它推动的是数据不约束的方向，
      而这个方向恰好是**把 ψ 的高频结构加进去以匹配 `Z_j` 的节点噪声**
      （psi 的 H1_rel 0.046→0.313 就是直接证据；与"偏差比场粗 8.8×/14×"互为印证）。
    - **结论**：**权重配平不是这个问题的解**。定义类残差在我们当前的逐点算子上，
     其最小值点包含"复现算子噪声"这一退化方向。必须先换**弱形式（刚度矩阵）残差**——
     它在单元上做平均、不放大节点噪声、梯度尺度 O(1)，且是 JOREK 真正求解的形式。
     在此之前，物理损失保持关闭（gate6 是当前最优工作点）。
38. **能量方程用错了并行传导系数：漏掉温度依赖 + `ZK_par_max` 封顶（差 17×/410×）**
    - 起因：用户要求"看 namelist 里传导项怎么设的"。实测 `jorek_namelist_spitest`：

      ZK_i_par_T = ZK_i_par * (Ti_corr/Ti_0)**2.5      ! 温度依赖
      if (ZK_i_par_T > ZK_par_max) ZK_i_par_T = ZK_par_max   ! 硬封顶

      分别超了 17× 和 410×**。

      `D_par=5e-2`、`D_par_imp=5e-2`、`D_perp(1)=5e-6`、`D_perp_imp(1)=5e-6`、

39. **CfC 的"节点间没有空间关系"对对流意味着什么（记录，训练阶段再处理）**
    - 架构事实：encoder / CfC 单元 / decoder **全部逐节点**，网格只出现在损失里
      （H1 图梯度、物理残差、磁轴）。一个节点的输出与其邻居**完全无关**。
    - **不等于"学不会对流项"**：连续 PDE 里 `−∇·(ρv)` 只依赖**同一节点**的
      `(ρ, ∇ρ, Φ, ∇Φ, ψ, ∇ψ, v∥)`，是**局部函数**；喂入一/二阶导数特征后，
      逐节点 MLP **原则上能把它乘出来**（gate5/gate6 实测：psi dR2 −0.21→+0.08、
      omega +0.02→+0.05，确有收益但幅度有限）。
    - **真正会出问题的两点**：
      ① **闭环时导数得由模型自己算**：训练时导数特征是教师给的；推理时必须用
         **模型解码场 + 图算子**现算（网格在推理时可获得 ✓），而这条反馈路径
         曾自激发散（pitfall #24）——属于稳定性工程问题，不是表达力问题。
      ② **单步跨过了整个帧间隔**：JOREK 一帧走 **50 个流体步**才把输运推完；
         CfC 一步跨 5（部分 run 250）个时间单位。逐节点模型在这种大步长下会学到
         **粗粒化的等效算子**（偏扩散），这正好解释"热力学场学得好（本就是扩散型）、
         输运场 psi/omega/v_par 学不动（dR2≈0）"。

43. **`--sub-steps` 不是"时间分辨率"，而是模型自由度：子步越多越差（#39b 被否，2026-10-01）**
    - 起因：pitfall #39b 建议"给 CfC 更多子步（2 → 8–16），让每步跨距接近 JOREK 的

    - **前置机制核查**（`tests/probe_time_consistency.py`，基线 checkpoint、v400、4 窗口）：
      ① ncps CfC（`mode="default"`）的 cell 更新是 `h_new = ff1·(1−t) + t·ff2`，

      ② 同一起点：一次 cell 走完 `dt` vs 两次 `(α, 1−α)` 的差别 =
         **1.03 × ‖Δu_true‖（pooled）**，与模型自身误差同量级
         ⇒ **积分步数是模型身份的一部分**，不可在推理时随意替换；
      ③ 但 **S 固定时**对 α 极不敏感：α ∈ [0.1, 0.9] 的差异全部落在
         0.102–0.104 × ‖Δu_true‖（pooled）⇒ "随机 α 训练"本身就是有效的时间自洽正则

         Phi/omega/v_par 的歧义很小（0.03–0.28）但它们的"1 步 vs 2 步"差异是 1.0 量级。

      （同 S 内对切分不敏感、跨 S 不可替换）。这意味着：
      ① 物理损失若要作用在"任意 `t*`"上，必须先让积分器**时间一致**

45. **时间一致性 vs 表达力：换成严格传播子（LTC 闭式解）掉一半精度（2026-10-01）**
    - 起因：#43/#44 确认 ncps CfC cell **不是时间传播子**（`ts=0` 不是恒等、切分歧义
      ≈21% 的更新量），而路线图要在"插值点 `t*`"上放物理损失——那要求积分器有时间语义。
      于是实现 `--cell ltc`（`JorekLTCProcessor`：`h(ts)=h0·e^{−rate·ts}+target·(1−e^{−rate·ts})`，
      `rate=|w_tau|+|tanh(ff1)|`、`target=tanh(ff2)`，**带 `h0` 项**），
      结构上满足恒等（缺陷 0）与近似半群（缺陷 <0.1%，`tests/probe_cell_semigroup.py`
      + `tests/test_ltc_processor.py` 守）。
    - 实测（同配方、同预算 60×20=1200 步、同 seed、held-out v400、按内层 val 选 best）：

      | 场 | **ncps（非传播子）** | **ltc（严格传播子）** |
      |---|---:|---:|
      | psi | **+0.275** | +0.077 |
      | Phi | **+0.281** | +0.030 |
      | Z_j | **+0.120** | +0.045 |
      | omega | **+0.222** | +0.010 |
      | rho / T_i / rho_imp / T_e | **+0.701 / +0.718 / +0.718 / +0.691** | +0.479 / +0.396 / +0.508 / +0.315 |
      | v_par | +0.016 | +0.026 |
      | **平均** | **+0.416** | **+0.210** |
      | 磁轴 中位 [cm] | 0.45 | 0.53 |
      | 训练 `train_mse`（末轮） | 3.66e-4 | 5.70e-4 |

      产物 `output/cfc_interp/long60x20_ltc`（脚本 `.scratch/n/run_ltc_cell.sh`）。
      LTC 的内层 val `mean_dr2` 从 ep5 起就卡在 **0.17–0.24** 的平台，60 轮没有起色
      ⇒ 不是"没训够"，是**这个函数族在当前参数化下学不动**。
    - **两个混淆项（必须记住，别当成干净结论）**：
      ① ncps 处理器还带一个 **LSTM mixed-memory** 捷径（`ncps.CfC(mixed_memory=True)`），
         它本身 `ts`-无关（也是破坏时间一致性的元凶之一），而 LTC 处理器**没有**它
         ⇒ 这 2× 的差距里有多少来自"cell 更新规则"、多少来自"少了 LSTM"未分离；
      ② LTC 的每次调用移动量被 `rate·ts` 限制（初始 `rate≤1`、`ts=dt/dt_scale=0.1`
         ⇒ 每次只往 target 走 ~10–20%），表达力可能被**初始化/时间尺度**卡住，
         而不是"传播子"这个约束本身不可行。
    - **结论（对路线图的直接影响）**：不能靠"换个 cell"就把物理损失放到插值点上——
      需要**既要时间一致、又要够表达**的积分器。下一步的三条候选（按性价比）：
      a) 给 LTC 加**可学习的时间尺度/多内部子步**（提高 `rate·ts` 的有效范围，
         并在 cell 内部做 2–4 次解析积分），先验证能不能把平台抬到 0.35+；
      b) 分离混淆项：保留 ncps 的 LSTM 捷径、只把 cell 换成闭式解（看差距归谁）；
      c) 接受"数据用 ncps、物理修正用一致性路径"的双轨（代价是两套动力学的接口要对齐）。
    - 一般教训：**"时间一致性"是一个会与拟合精度抢容量的硬约束**，不能只在指标表里
      加一条、而要当作架构取舍来评估（每次都要报"精度代价"）。

46. **把 CfC 改造成真正的传播子：LTC 闭式解 + 关掉 LSTM + 增广源积分（2026-10-01 用户要求）**
    - **判据**：传播子要满足 `Φ(0)=恒等` 与 `Φ(t₁+t₂)=Φ(t₂)∘Φ(t₁)`。旧 ncps cell
      （`h_new=ff1(1−t)+t·ff2`，`t=σ(t_a·ts+t_b)`）两条都不满足，而且
      `mixed_memory=True` 的 LSTM 捷径**完全不吃 ts**。实测（`tests/probe_cell_semigroup.py`，
      随机初始化，ts=1.0）：identity 缺陷 **1.0**（零长度步 <=> 一次完整更新）、
      split 缺陷 0.10–0.41、处理器级 0.10–0.24 ⇒ 与"时间"无关的离散映射。
    - **改造**（`src/models/ltc_cell.py::LTCCell`）：
      `rate = softplus(rate_net(backbone(x))) + 1e-6`（>0，天然耗散）、
      `target = tanh(target_net(backbone(x)))`（可 `--target-activation linear`）、
      `h(ts) = h₀·e^{−rate·ts} + target·(1−e^{−rate·ts})`；**删除 LSTM 支路**
      （`JorekLNNProcessor` 的 `mixed_memory` 默认 False，只有加载旧 checkpoint 才开）；
      backbone 默认 **256×2 层**（补偿 LSTM 让出的容量）；`CfCInterpolator` 默认 `cell="ltc"`。
    - **两个必须记住的设计决定**（精度的代价就在这里）：
      ① **默认 `state_dependent=False`**：`rate/target` 只看 cell 输入，不看 `h`
         ⇒ 半群性在浮点精度内成立；`--state-dependent` 恢复 h 依赖（真 LTC gating），
         但 split 缺陷回到 `O(ts²)`（ts=1.0 时 4.0e-02、ts=0.1 时 0.6–1.2% 的更新量）。
      ② **区间内输入固定**（只链 `h`）：旧实现把**解码后的 latent 回灌**成下一次 cell 的
         输入，这让系数依赖"子步序号"⇒ 破坏切分不变性（`recycle_latent` 已按 cell 区分：
         LTC 关、旧 ncps 保留以复现历史）。
    - **验收（用户指定协议，未训练随机初始化）**——`tests/probe_ltc_semigroup.py`：

      | level | variant | ‖Φ(0)h−h‖ | ‖h₁−h₂‖（0→1 vs 0→0.3→1） | /‖update‖ |
      |---|---|---:|---:|---:|
      | cell | **ltc（默认）** | 0 | **3.3e-07** | 3.7e-09 |
      | cell | ltc（float64） | 0 | **6.3e-16** | 6.8e-18 |
      | cell | ltc（state-dependent） | 0 | 3.6 | 4.0e-02 |
      | cell | ncps（旧） | 1.107 | — | — |
      | model | **ltc** | 0 | **2.9e-07** | 5.0e-08 |
      | model | ncps（旧） | 32.7 | 4.43 | 1.3e-01 |

      （model 级 `dt=dt_scale` → ts=1.0；10 段等分链 3.7e-07。）满足"1e-6 以内"。
      单测守在同一处：`tests/test_ltc_cell.py`（恒等、float32/float64 半群、rate>0、
      **切分不变性**、积分器精确性）。

51. **度量口径最终定稿：用"与前后两帧的归一化相似度 `closer`"，弃用 mean dR2（2026-10-01 用户意见）**
    - 用户的批评（全部成立）：
      ① R² 本身就回答"有没有复现下一帧"——它是**预测场 vs 真值场**的误差，
         而"有没有在照抄前一个场"要**同时**跟前一帧比，才能判断；
      ② 把 dR2 当作"有没有学到东西"不科学；
      ③ **命名错误（我的锅）**：我们的 `dR2` **从来不是 ΔR²**，它的定义是
         `1 − ‖Δ_pred−Δ_true‖²/‖Δ_true‖²`，即"把增量当被预测量时的 R² / 相对 persistence 的技能"。
         名字容易被读成"R² 的变化量"，已在文档里改称 **`skill_pers`**，不再叫 dR2。
    - **新主指标（用户方案，已实现）**：对每个场同时算两个距离
      `d_true = ‖u_pred − u_true‖`、`d_prev = ‖u_pred − u_prev‖`，定义

      ```
      closer = d_true / (d_true + d_prev)      ∈ [0, 1]
      ```

      读法：**0 = 预测正好落在下一帧；0.5 = 恰好落在两帧中间（完全模糊）；1 = 预测就是前一帧（纯照抄）**。

      不需要按 dt 分层（见下）。逐窗口取中位数（`closer_median`）以抗个别窗口。

50. **"窗口 dt 要不要一致？"——理论上不需要，但有三个必须控制的接口（2026-10-01 讨论）**
    - **结论：不需要（也不应该为了这个去重采样）。** 我们训练的是连续时间传播子
      `dh/dt = −rate·(h − target)`，其解 `h(t+dt)` 只依赖 `(h, x, dt)`；dt 可以任意、
      非均匀。不等间隔采样反而是**信息**（同一动力学在不同时间尺度上的观测），
      而强制等间隔会把模型退化回"固定步长的离散映射"——那正是 pitfall #43 里
      ncps cell 的问题。实测也支持：把 h 依赖加回来（破坏精确半群）在最优 lr 下更差
      （0.252 vs 0.323 mean dR2；`dR2(med)` 0.280 vs 0.389）。
    - **但有三处必须控制**：
      ① **损失权重**：现在的 data loss 是"逐区间等权"。dt 分布若是"40% 细 + 30% 粗"，
         等权就等于让信噪比低的细区间占同样权重。想要的是"每单位时间等权"（按 dt 加权）
         或"分桶加权/分桶采样"——这是一个**待定的设计点**，与 dt 是否一致无关。
      ② **度量必须按 dt 分层**（#49 已落地）：否则跨 run/跨桶的对比没有意义。
      ③ **物理残差要限定 dt 区间**：细 dt 时真实步长落到表示精度以下（#49 的 `*` 标记），
         残差会被表示误差支配；粗 dt（≥100）时"区间内系数冻结"的松弛假设可能失效。
         所以将来在 `t*` 上放物理损失时，应按**可分辨的 dt 区间**（例如 TQ 附近的 0.5–10）
         采样，而不是全范围均匀。
    - 附注：数据层面同一窗口内 dt 本身就是变化的（连续帧 + "早密后疏"导出表），
      所以"窗口 dt 一致"在现有数据上既做不到也没必要；真正要做的是把 dt
      **显式喂进网络**（`--input-dt`，已做）并按上面的三条控制使用它。

      * **监督区间（dt）分布**：训练集 2512 个区间 —— 中位 **5.0**、均值 17.5、最大 **250**；
        <1 占 12.6%、[1,3) 26.7%、[3,7) 17.8%、[7,15) 10.8%、[15,30) 14.8%、[30,100) 14.5%、
        ≥100 占 2.9%。
      * **held-out run 的评测窗口**（60 个区间）—— 中位 **50.0**、均值 52.1、最大 100；
        [15,30) 35%、[30,100) 46.7%、≥100 16.7%。
      ⇒ **训练中位 dt=5，评测中位 dt=50**：held-out 评估实质上是 dt 上的**外推**，
        而且跨 run 对比被 dt 分布严重混淆（doc 里"dt=5.0、50 流体步/帧"的说法只对少数帧成立）。
    - **代码层面 dt 确实进了网络**（回答用户问题）：
      `CfCInterpolator.advance` → `timespan = dt / dt_scale`（默认 50）→
      `JorekLTCProcessor.forward(time_steps=...)` 按 `batch_index` 展开成每节点 `[N,1]` →
      `LTCCell.forward`：`decay = exp(-rate * ts)`、`h ← h·decay + target·(1−decay)`。
      所以**每个窗口用自己的 dt**（v400 的 dt=50 → ts=1.0；ang12 的 dt=2 → ts=0.04），
      而且 LTC 的重写让 dt 有了物理含义（`rate·ts` 决定这一步松弛多少）。
      但要注意两条：
      ① **编码器看不到 dt**（输入只有 u、一/二阶导数、5 通道源控制），dt 只从 cell 的指数进去；
      ② **源控制没有乘 dt**：投影源是区间平均量，按"冲量=源×dt"的物理直觉，长 dt 区间的
         权重目前只能靠 cell 的 `ts` 隐式表达。
    - 处置建议（未做，等用户定）：① 把 dt（建议 `log1p(dt)` 或 `dt/dt_scale`）作为**显式输入特征**
      接进 encoder（与"输入冻结"不冲突，半群性不受影响，见 #46）；② Gate 报告按 dt 分桶
      （细/中/粗）而不是只给总平均；③ 修正文档里"50 流体步/帧"的表述；
      ④ 若要做"插值点物理损失"，必须先明确"一个帧区间"在各 run 里到底有多长。

54. **1000 epoch 恒定 lr 会越过最优点（~ep620 后失稳）；磁轴硬 argmax 指标在该精度下失效（2026-10-02）**
    - 实验：`ltc_dt_h{1,2}_1000`（LTC + `--input-dt`，lr 3e-3 恒定，1000 epoch × 20 步，
      `--save-best-metric closer`，manifest_h5 16 帧窗口）。
    - **现象一：最优点在 ~ep620，之后失稳**
      * h=1：min val_mse **0.01237 @ep626**、min closer **0.4826 @ep634**（train_mse 6.6e-5），
        但到 ep700 时 closer 跳到 **0.77**、train_mse 反弹到 3.3e-4、val_mse 0.0222
        ⇒ 不是平滑过拟合，是**训练失稳**（恒定 lr 3e-3 下后期的尖峰）。
      * h=2：同样是 ~ep610–630 最好（min val_mse 0.0353 @ep630、min closer 0.449 @ep612），
        之后 val_mse 在 0.04–0.18 之间剧烈震荡。
      ⇒ `--save-best` 选出的 checkpoint（ep634 / ep612）是对的，但**1000 epoch 恒定 lr 是浪费**：
        超长训练必须配 **lr 衰减**（或更短的预算）。
    - **现象二：held-out 最好成绩（h=1, ep634）**
      R² **0.9933** / relL2 **0.0660** / closer **0.465** / skill_pers(中位) **0.660**
      —— 四项都是目前最好（对比 200 epoch 版 0.9922/0.0729/0.521/0.632，ncps 0.9909/0.0797/0.598/0.424）。
      分场 relL2：psi 0.0064 / T_i 0.020 / rho 0.043 / rho_imp 0.043 / T_e 0.048 / Z_j 0.053 /
      v_par 0.083 / **Phi 0.145 / omega 0.153**；closer：T_i 0.281 / rho_imp 0.313 / rho 0.321 /
      psi 0.355 / T_e 0.430 / Z_j 0.560 / omega 0.574 / v_par 0.653 / **Phi 0.700**。
    - **现象三：磁轴指标（硬 argmax）在该精度下失效**。h=1 报告 axis 中位 **23.8 mm**（此前 4.5–5.3 mm），
      逐窗口核对后确认是**伪影**：psi 顶部极平——真轴上 `psi_pred=0.5030` vs `psi_true=0.5040`
      （场量程 1.05，差 0.1%），argmax 在相邻节点间抖动即可产生 2–4 cm"位移"。
      ⇒ 磁轴指标应改为 ①**真轴节点上的 psi 值差**，或 ②**抛物线插值峰位**；硬 argmax 在

    - 口径提醒：h>1 时 `closer` 的参照帧离得更远（分母更大），**跨 h 不可直接比较 closer**；
      跨 h 比较应看 R² / relL2 / `derr/|u|`。
55. **horizon 语义澄清：逐帧插值 h 次（rollout），且**每段内部必须随机切分**（2026-10-02 用户要求）**
    - 用户澄清：对比实验要的不是"一次跨 h 帧"（`jump`），而是 **`t_{k+h} − t_k = Σ_{i} δ_i t`**：
      网络**逐帧插值 h 次**，每次跨一个**记录间隔** `δ_i t`（中间记录帧作为各步的编码输入、
      hidden 链式传递），数据损失只落在第 h 帧。
    - **"不是均匀时间间隔而是随机的"在实现里体现为两层**：
      ① **记录的 δ_i 本身就非均匀**（数据是"早密后疏"导出表）：例如 manifest_h5 的
         rollout h=5 样本里 δ 序列 = `[25, 44, 50, 50, 50]`（Σ=219）、`[50,50,88,100,100]`（Σ=388）、
         `[44,50,50,50,88]`（Σ=282）——绝不是 `Δt/5` 的均匀网格；
      ② **每个记录间隔内部**由 CfC 链切成 `--sub-steps` 段，切分点是**随机分数**
         （`sample_split_fractions(mode="random")`，ADR-0013），不是等分。
      之前 rollout 分支里误用了 `model.step(sub_steps=2)`（**等分**），已改为 random 切分的
      `multi_substep`（jump 与 rollout 两条分支现在都随机切分）。
    - **训练预算修正**：恒定 lr 3e-3 在 ~ep620 后失稳（#54），所以本轮 rollout 三组
      （h=1/2/5）统一用 **cosine lr 3e-3 → 3e-4**、1000 epoch × 20 步、
      `--save-best-metric closer`，manifest_h5（16 帧窗口）共用窗口。
    - **磁轴指标同步修正**：硬 argmax 在 psi 顶部平坦时没有分辨力（#54），
      `eval_phase3_structure.py` 现在**额外**输出
      `psi at the TRUE axis node: |pred−true|/max|psi|`（中位/p90，写进 `--json`
      的 `axis_value_rel_error`），并把硬 argmax 标注为 legacy（仅供参考）。
    - 产物：`.scratch/n/run_rollout_sweep.sh`（串行）、日志 `.scratch/n/rollout_sweep.log`、
      `output/cfc_interp/ltc_roll_h{1,2,5}_1000/`。

    - **训练集重规划**（3 个 manifest，`stride=1`，`horizon=1` ⇒ 窗口 = `burn_in + 2` 帧，

58. **"旧的最好成绩"有一部分是评测窗口选得容易：换到全窗口后 R² 0.994 → 0.974（2026-10-02）**
    - 现象：新五组（`step_s*_b10`、`warm_b*_s2`）在 `--inner all`（held-out run 的全部窗口）下
      mean R² ≈ **0.971–0.976**、relL2 ≈ 0.104–0.114，明显低于此前报的 R² 0.9937 / relL2 0.0663。
    - 真因**不是模型变差，而是测试窗口的 dt 构成不同**：旧评测用 `--inner val` 的 13 个窗口，
      其中 12 个落在 **15–60** 这个最容易的 dt 桶；新的全窗口集包含 28 个 **3–15**（细间隔）
      与 9 个 **≥60**（粗间隔）窗口。**同一个 dt 桶内**两者其实相当：

      | 评测集 | 窗口数 | 15–60 桶 closer | 15–60 桶 dR2pool | 15–60 桶 derr/\|u\| | 3–15 桶 derr/\|u\| | ≥60 桶 derr/\|u\| |
      |---|---:|---:|---:|---:|---:|---:|
      | 旧（16 帧 manifest, "val" 13 窗） | 13 | 0.453 | +0.556 | 0.0612 | — | — |
      | 新 `step_s1_b10`（65 窗） | 65 | 0.458 | **+0.625** | **0.0529** | 0.1112 | 0.2086 |
      | 新 `step_s2_b10` | 65 | 0.548 | +0.475 | 0.0645 | 0.1096 | 0.2247 |

      ⇒ **"最好的 R² 0.994" 是在最易桶上量出来的**；换成全窗口，绝对水平是 R² ≈ 0.974。
      以后所有 Gate 必须写清"评测窗口集合 + dt 桶构成"，否则跨实验无法比较（呼应 #49）。
    - 顺带修掉一个真问题：`manifest_b10` 里 held-out run 只有 **1 个 val 窗口**（12 帧窗口 +
      分块划分把它的窗口几乎全分给了 train/dropped）。因为整条 held-out run 都不参与训练，
      评测改用 `--inner all`（65 窗）才是正确做法；`eval_phase3_structure.py` 已加该开关。

59. **步数 S=1/2/5 与 warm-up 10/15/20 的扫描结果：传播子步数不变性成立；更长 warm-up 没有收益（2026-10-02）**
    - 训练集重规划后（每窗口 1 个监督区间：base=warm-up 末帧 → target=紧接着的那一帧），
      五组各 1000 epoch（cosine lr 3e-3→3e-4）、每 epoch 640 个监督样本、同 seed、
      评测集统一为 held-out run 的全部窗口（65/60/55 窗）。
    - **Phase A（步数，同一 manifest_b10、同一目标帧）**：

      | S | R² | relL2 | closer | 15–60 桶 derr/\|u\| |
      |---:|---:|---:|---:|---:|
      | 1 | **0.9756** | **0.1042** | 0.481 | **0.0529** |
      | 2 | 0.9741 | 0.1095 | 0.582 | 0.0645 |
      | 5 | 0.9735 | 0.1080 | 0.473 | 0.0611 |

      ⇒ 三者差异 ≤0.2%（R²）/5%（relL2），**没有"步数越多越差"的系统性趋势**
      （S=5 与 S=1 基本并列，S=2 略差但仍在单次运行的噪声量级）。
      这正是 LTC 精确传播子应有的行为（对照 #43：旧 ncps cell 在 S=8/25 时平均 dR2 从 +0.19 掉到 +0.08/+0.03）。
      **结论：步数不再是模型自由度，重写的验收通过。**
    - **Phase B（warm-up 长度，S=2）**：

      | warm-up | 窗口数 | R² | relL2 | closer | 15–60 derr/\|u\| |
      |---:|---:|---:|---:|---:|---:|
      | 10 | 65 | 0.9741 | 0.1095 | 0.582 | 0.0645 |
      | 15 | 60 | 0.9721 | 0.1108 | 0.501 | **0.0571** |
      | 20 | 55 | 0.9714 | **0.1140** | 0.528 | 0.0683 |

      ⇒ **更长 warm-up 没有带来收益**（R² 略降、relL2 略升；15≈10，20 最差）。
      注意三个 manifest 的窗口/目标帧不同（warm-up 越长，目标帧在段内越靠后），
      且 Δt 分布虽一致但样本集不同 ⇒ 这条结论是"没有正向证据"，不是"越长越差"的强结论。
    - 附带教训：**训练侧 inner-val MSE 在 manifest 之间不可比**
      （b10 三组 0.041–0.048，b15/b20 0.0145/0.0186，但 held-out 上 b10 更好）
      —— 不同 manifest 的 val 窗口集合不同，不能拿它跨 manifest 比较模型。
