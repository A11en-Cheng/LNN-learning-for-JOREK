# ADR-0012：评估协议采用 blocked 窗口划分 + Leave-One-Run-Out

状态：已接受（2026-09-27）

## 背景

只有 10 个纯 2D run，每个 run 一次 SPI 注入，run 之间的场景参数（速度、角度、碎片数、注入量）不同。
固定 run 级 train/val/test 划分会让验证结果强烈依赖抽到哪个 run（可能完全 OOD，评估悲观且不稳定）；
窗口级随机划分又因滑窗重叠造成数据泄漏，使插值自洽性指标虚高。两种主张需要两套协议，不能用一套划分
同时回答。

## 决定

1. 数据构造只有一套：统一的、物理一致的窗口语料；train/val/test 只是语料上的分配标签。
2. **插值协议**（模型选择与插值 gate）：同一 run 内按连续时间块划分 train/val；
   purge（训练窗口与验证窗口不共享任何帧）是硬要求；窗口充足的 run 再追加一个窗口跨度的 embargo，
   窗口不足的 run 保持 purge-only 并把该模式记入 manifest。该协议回答"任意时间插值是否自洽"。
3. **场景协议**（最终 gate）：Leave-One-Run-Out，10 折，每折留一个 run；报告逐 run 指标与分布，
   不使用 frame-pooled 平均值作为唯一结论。该协议回答"换注入场景是否仍成立"。
4. LOO 只用于最终评估，不得用于调参或早停（避免选择泄漏）；模型选择用插值协议的内层划分。
5. 成本受限时可用 5 折分组（每折 2 个 run）近似；"留一个场景家族"（如 v400）只作外推分析。

## 后果

- 每个 run 的 post-`t_ns` 窗口在其 LOO 折中完整留出一次；指标按 run/事件级聚合。
- 内层划分中因 purge/embargo 被排除的窗口（``inner == "dropped"``）只在插值协议里失效；
  在 LOO 场景协议中，它们仍属于训练 run 的窗口并参与训练。
- 统计量必须按折重新计算（train-only），不能用全量统计量。
- 报告必须同时给出插值协议与 LOO 结果，二者不能互相替代。
